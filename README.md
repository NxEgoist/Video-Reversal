# 视频反推 Prompt

本地单用户视频分析工具：检测镜头、采样画面，调用多模态模型生成文生视频 / 图生视频中英双语 Prompt。结果、参考帧、人工编辑保存在本地 `data/`。

协作开发请先阅读 [协作开发协议](AGENTS.md) 和 [项目理解与开发规格](PROJECT_SPEC.md)；AI 助手应按规格追踪当前代码与测试。

## 启动

需要 Python 3.10 以上、FFmpeg 和 FFprobe。首次运行：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

打开 http://127.0.0.1:7860 ，在「模型与 API 设置」选择服务商，填写模型和密钥，然后点击「测试连接」。测试连接只验证文本请求与 JSON 返回，不验证图片输入能力。分析视频时采样画面会发送至所选服务商，可能产生费用。

| 服务 | 配置 |
|---|---|
| Gemini 原生 API | 默认 `gemini-2.5-flash`，密钥可填写或使用 `GEMINI_API_KEY` |
| OpenAI | 默认 `gpt-4o`，密钥可填写或使用 `OPENAI_API_KEY` |
| 硅基流动 | 默认 `Qwen/Qwen3-VL-32B-Instruct`，密钥可填写或使用 `SILICONFLOW_API_KEY` |
| 通义千问 | 默认北京地域的兼容接口和 `qwen-vl-max`；密钥可填写或使用 `DASHSCOPE_API_KEY`。可改为对应地域或工作空间地址 |
| OpenRouter | 填写支持图片输入的模型名；密钥可填写或使用 `OPENROUTER_API_KEY` |
| 自定义（OpenAI 兼容） | 填写模型名、基础地址和密钥；或使用 `CUSTOM_API_KEY`。支持无密钥的本机接口 |

自定义服务应支持 OpenAI 格式的 `/chat/completions`、`image_url`（base64 图片）和返回 JSON 的能力。地址可填写基础地址（例如 `http://127.0.0.1:11434/v1`），也可填写完整的 `/chat/completions` 地址。远程地址必须使用 HTTPS。本机模型也需支持图像输入；并非所有兼容接口都支持视觉模型或此格式。

密钥可以通过页面、环境变量或项目内 `.env` 提供，按页面输入、环境变量、本地配置的顺序读取；项目 `.env` 已排除在版本管理和导出包之外，密钥不会写入任务记录。`.env` 为本地明文文件，请保护设备及文件访问权限；切换服务商会清空页面输入框。不同服务商的密钥应分别填写，不应发给不受信任的自定义地址。已有任务可切换模型后重新分析单个镜头；“分析全部镜头”会跳过已完成的镜头。

1. 上传 180 秒以内的 MP4 / MOV（不超过 200 MB），创建任务。
2. 点击分析全部镜头，选择镜头查看分析与证据。
3. 可编辑 Prompt、填写 JSON 人工修正、调整切点或参考帧。点击保存；切点改变后重新分析受影响镜头。
4. 导出 ZIP，包含提示词、分析 JSON 和参考帧。任务 ID 可用于恢复之前的任务。

## Clip 分割与边界证据

创建或恢复任务后，在工作台展开「Clip 分割与边界证据」，点击「加载片段列表」。每个原镜头默认是一个片段；可输入原视频时间拆分，也可与同一镜头内的下一个片段合并。原镜头分析不会被覆盖，拆分或合并前的片段数据保留在任务历史中。

React 工作台中，当 Clip 与原镜头范围完全一致且没有独立结果时，会注明来源并展示镜头分析；保存片段提示词会创建独立副本，不修改原镜头。拆分后的片段不会继承整镜头结果。

选择片段可查看原视频首尾帧及边界采样帧；帧记录包含实际解码时间戳。点击「独立分析此片段」调用当前模型，片段分析与原镜头分析分开保存，可能产生费用。边界采样会加入分析，但画面采样仍受模型和抽帧方式限制。

「全片上下文」以 JSON 记录素材卡、片段起止状态及相邻衔接；加载后填写并保存。只有已确认且未过期的素材与状态用于提示词生成；画面观察仍基于片段帧。拆分、合并会使旧片段关联待核对；保存上下文后，已有片段提示词需重新分析。系统不会自动保证人物一致或动作衔接。

导出包包含 `clips.json` 与边界帧，案例保存和恢复包含已提取的边界帧。当前为人工切分，尚未实现基于语义动作的自动切分、全片自动关联或直接视频生成。帧序列以约 250 毫秒采样，并非完整逐帧播放。

## 全片复现流程

保存提示词与人工修正后，在工作台展开“全片复现流程”，点击刷新。计划按镜头整理两条候选生成路线、目标时长、参考帧、主体关联、动作证据和待核对事项，并给出剪辑、声音与验收步骤，不增加模型请求。

中途参考帧仅对应后续动作，计划会标出前段缺口。原始模型、种子与参数仍未知；目标时长不代表生成平台支持该长度。编辑后需刷新预览，切换任务会清空旧预览。

导出 ZIP 同时包含 `reconstruction.md` 和 `reconstruction.json`，始终基于最新保存内容。完整研究与后续优化方案见 [OPTIMIZATION_PLAN.md](OPTIMIZATION_PLAN.md)。

## 抽帧与对比

在镜头工作台的「采样与对比」中：

- **等间隔**保留原版 2 FPS 与首、中、尾采样；**快速（1 FPS）**减少基础采样帧和部分模型请求，可能漏掉快速动作，必要时使用其他策略或人工补帧。
- React 工作台「镜头与高级功能」可在本机检测黑场候选，核对后可将当前镜头排除在批量分析之外，也可恢复；手动分析仍可使用，原片和时间线不会删除。检测每约 250 毫秒抽查画面，暗场或短暂画面可能误判，应对照原片。
- **变化驱动**保留首、中、尾和每两秒兜底帧，并在画面变化时补帧；阈值是初始经验值，需要实际素材验证。
- 点击「预览采样帧」查看缩略图、时间和选择原因，不会调用模型。输入原视频时间并添加补帧后，重新分析本镜头使其参与分析。
- 「对比三种抽帧策略」会在同一镜头上及 Prompt 专用各运行一次分析，使用当前服务和模型及单帧发送，展示三组双语提示词、基础采样帧数、耗时和服务商返回的用量。对比不会覆盖现有分析；三组调用均可能产生费用。
- 图像发送方式可选单帧或四格拼图；拼图完整保留画面并标注时间，但细节变小，费用取决于模型。对比按钮固定单帧以便只比较抽帧策略。补看帧不计入基础采样帧数。

## 当前限制

默认只分析画面；可手动将全片音轨发往硅基流动做对白转写，也可手动确认跨镜头主体。暂未提供自动主体识别、对白时间戳和根据目标模型的生成片段规划。长镜头按最多 24 帧分窗口分析；最多对两个待确认区间补帧。片段切点为检测候选，建议人工检查。参考帧未经去字幕或修复。模型结果并不保证准确复现原视频。


## Prompt 专用策略（第三套）

新增 TransNetV2 + 镜头内变化积分 + 局部运动 + 清晰度筛选。保留动作前中后三帧和时间覆盖，避开转场混合画面，分析窗口不跨检测到的转场；用户补帧仍保留。原来的两套策略不变，默认仍为等间隔。

```bash
source .venv/bin/activate
pip install -r requirements-transnet.txt
python app.py
```

本机已下载官方权重到 `models/transnetv2/`。该策略首次加载模型和运行全片转场检测较慢，后续使用缓存。缺少模型或依赖时会明确报错。算法参数、设计边界及来源见 [ALGORITHM.md](ALGORITHM.md)。

## 参考帧、覆盖核对和续跑

- 在镜头工作台输入原视频中的秒数，点击「预览并选择参考帧」；无需先调用模型。导出的参考帧为原始分辨率 JPEG，实际画面按视频帧时间定位，可能与输入时间有一帧左右的差异。它不会自动去除视频自带的字幕或水印。
- 选镜头中途画面后，图生视频提示词针对参考帧之后的内容；跨越参考时间但状态不明的动作会列为待核对，不保证模型必然正确理解。手动选定的参考帧在重新分析时保留。
- 「分析证据与人工修正」里显示模型自报的动作阶段覆盖及待核对阶段。自报不是准确率证明，模型仍可能漏写或虚构；人工修改后也需要重新核对。
- 分析中断后，用相同的视频、镜头边界、采样策略、模型与输入方式点击「继续上次分析」，已完成窗口可复用；更改相关设置后会重新分析。点击「重新分析本镜头」从头处理。已发生的 API 调用仍可能产生费用。
- 如果主要画面分析完成，但动作补看的请求超时，工具会用已完成的观察生成并标注「部分结果」；未完成的时间段会保留在分析证据中，界面和导出结果均有提示。点击「继续上次分析」可重试补看。若主要分析或最终生成超时，会显示具体阶段；已有成功窗口仍可继续。超时请求也可能产生费用，部分结果不能视为完整的动作判断。
- Prompt 专用 v2 在每 12 秒窗口内按时长分配上限，并将相邻运动事件的候选间隔设为 750ms，以减少重复帧。快速小动作可能被漏采，可通过手动补帧或其他策略对照。


## 对白与跨镜头主体

- 在左侧「音频与对白」中，选择硅基流动后手动点击「提取对白」。请求会把整段音轨发送到硅基流动，可能产生费用；返回全片文本，没有时间戳，不能据此确定对白属于哪个镜头。空结果不代表视频一定没有语音。音乐、音效与音轨分离尚未支持。
- 可手动修订并保存转写；再次转写保留人工修订，原始转写和修订都写入任务 JSON，Markdown 导出使用修订版。视觉分析不会把对白当作画面事实。
- 在「跨镜头主体」中填写相同主体标签和统一外观，并在各镜头分别点击「保存并关联主体」。重新生成这些镜头的 Prompt 时会带上已确认的关联；系统不自动识别身份，也不保证生成模型一定保持一致。更新外观会将受影响的已完成镜头标记为待更新。

硅基流动视觉请求会把较长的帧序列拆成最多 8 帧的窗口，相邻窗口保留少量重叠，转场边界仍会隔开。窗口缩小有助于控制单次请求负载，但会增加请求次数，实际速度和费用以服务返回为准。程序仅在服务商预设地址使用自动读取的对应密钥；若把该预设改成其他域名，需明确输入该地址专用的密钥。

## 保存案例

在左侧「案例库」填写名称并点击「保存当前案例」。案例以独立快照保存在本机 `data/cases/`，包含视频、各镜头分析、当前编辑框中的提示词、参考帧、对白和已关联主体；不会保存 API 密钥。若切点或主体关联尚未保存，请先在对应区域保存。

从下拉列表选择案例后点击「打开案例」，会创建新的工作副本供继续编辑，保存的案例内容不受影响。要把修改后的版本也保存下来，可再次保存为新案例。案例与项目数据都保存在本机，请根据自己的需要备份。

## React + FastAPI 工作台（迁移中）

现有 Gradio 工作台暂时保留。新工作台支持视频与镜头、Clip、采样、模型分析、提示词、上下文、音频、案例与导出；详细迁移边界见 [FRONTEND_MIGRATION.md](FRONTEND_MIGRATION.md)。

```bash
pip install -r requirements.txt -r requirements-api.txt
python -m uvicorn backend.api:app --host 127.0.0.1 --port 8000
```

另开终端：

```bash
cd frontend
npm install
npm run dev
```

打开 http://127.0.0.1:5173。当前仅用于可信本机，服务没有远程访问认证，请勿暴露到公网。

React 工作台的「模型配置」集中保存服务商设置，包括硅基流动、OpenCode Go 和原有服务商。硅基流动默认复用已有的 `SILICONFLOW_API_KEY`；OpenCode Go 默认读取本机 OpenCode 的 Go 地址对应密钥，也可填写 `OPENCODE_GO_API_KEY`。页面可保存新密钥；`.model-settings.json` 为权限受限的本地明文文件，已排除在版本管理外，密钥不会返回页面、写入任务或导出。切换默认服务商后，片段和镜头分析均使用该配置。更换远程地址时必须输入该地址专用密钥。OpenCode Go 的模型、接口与图片输入能力可能变化，需自行验证；文本连接成功不代表支持视频帧分析。

片段提示词在页面内切换片段或配置页时保留未保存草稿；刷新或关闭页面前仍须保存。批量分析遇到单个镜头失败时会继续其他镜头，结束后显示未完成项。

模型请求发生超时、网络异常、限流（429）或部分服务端临时错误时，最多自动重试一次；若服务要求等待超过 10 秒则不提前重试。响应 JSON 无效或为空时会重新请求一次。认证、权限或其他不可重试错误会直接提示。重试可能延长等待时间并产生额外费用；补看失败时保留已完成的观察作为部分结果。不会自动将素材发送到其他服务商。
